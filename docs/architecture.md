# 프론트엔드 아키텍처

## 기본 원칙

프로젝트는 `app → views → widgets → features → entities → shared` 순서의 FSD 구조를
사용한다. 상위 레이어는 하위 레이어만 참조하며, 슬라이스는 행동이 아닌 비즈니스 도메인
단위로 나눈다.

## 레이어별 책임

| 레이어     | 책임                                     | 판단 기준                                              |
| ---------- | ---------------------------------------- | ------------------------------------------------------ |
| `app`      | Provider, 전역 설정, Route Handler 구현  | 특정 화면이나 도메인에 속하지 않는 앱 전체 책임인가?   |
| `views`    | 라우트에 대응하는 완성된 화면 조립       | 화면의 배치와 사용자에게 보이는 흐름을 설명하는가?     |
| `widgets`  | 여러 도메인을 조합한 독립적인 복합 UI    | 여러 화면에서 재사용되는 큰 UI 블록인가?               |
| `features` | 도메인별 기능 실행과 상태·규칙 관리      | API 요청, 기능 상태 또는 업무 규칙을 처리하는가?       |
| `entities` | 여러 feature가 공유하는 핵심 데이터 모델 | 둘 이상의 feature 슬라이스가 같은 데이터를 공유하는가? |
| `shared`   | 도메인을 모르는 범용 코드                | 프로젝트의 비즈니스 개념 없이도 사용할 수 있는가?      |

- 재사용 횟수만으로 레이어를 결정하지 않는다.
- 한 화면에서만 사용하더라도 API 요청이나 도메인 규칙을 담당하면 `features`에 둘 수 있다.
- 반대로 특정 화면의 배치와 표현만 담당하면 재사용되더라도 우선 `views` 또는 `widgets`의 책임을 검토한다.

## 상태와 검증 판단 기준

### 화면 상태

- 모달·바텀 시트의 열림 여부, 오류를 화면에 노출할 시점처럼 표현에만 영향을 주는 상태는
  `views`에 둔다.

### 기능 상태

- API 요청의 로딩·성공·실패 상태처럼 기능 실행 과정에 속하는 상태는 해당 `features`에 둔다.

### 입력값 검증

- 값 자체가 업무 규칙에 맞는지는 해당 `features`에서 판단하고, 오류를 언제 어떤 모양으로 보여줄지는 `views`에서 결정한다.
- 향후 서로 다른 feature 슬라이스에서 동일한 모델이나 규칙을 공유하게 될 때만 `entities`로 이동한다.
- 사용처가 생기기 전에 빈 entity나 추상화를 만들지 않는다.

## 코드 적용 예시

| 코드                                      | 위치                  | 이유                                   |
| ----------------------------------------- | --------------------- | -------------------------------------- |
| 카카오 인가 URL 생성과 이동               | `features/auth`       | 로그인 기능을 실행함                   |
| 활성 팀 스페이스 조회와 요청 상태         | `features/team-space` | 팀 스페이스 기능의 API와 상태를 관리함 |
| 온보딩 입력값과 유효성 규칙               | `features/team-space` | 팀 생성·참여 도메인의 상태와 규칙임    |
| 첫 페이지와 온보딩 화면 구성              | `views`               | 기능과 UI를 조립해 완성된 화면을 만듦  |
| 바텀 시트 열림 여부와 입력 오류 노출 시점 | `views`               | 화면 표현을 위한 상태임                |
| 클립보드 복사                             | `shared`              | 특정 도메인을 모르는 범용 기능임       |

## Public API

- 각 슬라이스 외부에서는 반드시 슬라이스의 `index.ts`를 통해 import한다.
- 세그먼트 내부 경로를 직접 참조하지 않는다.
- 서버 전용 export와 클라이언트 export가 충돌하는 실제 빌드 문제가 발생할 때만 `index.server.ts`를 추가한다.
